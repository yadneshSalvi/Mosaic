# Mosaic
See what your screenshots reveal together, then edit the evidence that connects them.

## The Unique Kernel
Mosaic protects a chosen association while preserving the useful content an author needs to publish. It shows exact source-backed paths across a screenshot bundle, finds the fewest candidate masks compatible with Keep visible choices, and checks the actual exported pixels. A separate opt-in asks a fresh model context what the exported files reveal, without giving it the protected answer.

## Who It's For
A designer or developer preparing a client case study with screenshots from support, project tracking, and internal directories. Today they inspect files separately and can miss what repeated identifiers reveal across files.

## The Core Loop
Open an inspectable fictional bundle or import PNG/JPEG images. Choose the protected source and target. Follow links back to visible source regions; confirm or reject suggested facts. Mark useful regions Keep visible, apply a constrained repair, export new images, and inspect pixel checks. Optionally consent to a fresh reading of only the exported PNGs and starting fact; inspect proposals and reopen review on those exported pixels.

## Inspiration & Identity
A precise evidence desk: warm paper, ink typography, cobalt connections, fine dot grid and tactile document cards. The interface is a working canvas rather than a marketing page. This direction is an implementation recommendation under delegated design authority.

## Why This Matters to the Learner
The learner selected Mosaic for this hackathon and requested meticulous planning, polished implementation, local verification and incremental public commits. No additional personal motivation or learning outcome was supplied.

## What "Working" Looks Like
Three actual fixture images reveal Incident 042 → client C-17 → Project Cedar → Northstar Health, with a second route via an operations channel. A recommended customer-name mask breaks both routes. Keeping the public customer credit visible changes the repair to two smaller incident-identifier masks; impossible preservation choices are explained. Downloaded PNG bytes are decoded and every mask, unmasked pixel and kept region is checked. A fresh reading can surface a surviving occurrence missed by the original graph, while an empty result remains only a model observation. An import flow analyzes new files and lets the user ground proposed facts.

## The POC Boundary
One in-memory workspace, 2–6 PNG/JPEG images, directed typed evidence, bounded route search, exact minimal region cut under pixel-preservation constraints for bounded small graphs, real raster export and observed pixel checks. The sample graph/export loop works offline/keyless. Optional live extraction and context-separated reading of exported PNGs use a server-side key and separate explicit cloud consent. The latter currently proposes customer attributions only; no result is a privacy certification.

## Later
Local OCR, more formats, manually drawn redaction regions, saved workspaces, local post-export OCR and independent-provider inference evaluation.

## Explicitly Cut
Accounts/database/collaboration: unrelated to the proof. PDF: adds parsing and hidden layers before image loop is proven. Generic privacy scoring and safety guarantees: not justified by bounded evidence. Deployment: optional and not authorized in this phase.
